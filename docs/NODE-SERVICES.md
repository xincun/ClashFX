# Multi-Node Fixed Ports & Watchdog / 多节点服务

多节点服务（实现位于 `core-engine/internal/nodeservices/`）在 **macOS** 与 **Windows** 上提供完全一致的多出口固定端口映射、顺序下载测速与后台健康巡检能力。

入口：控制中心左侧 **多节点服务** 页面。

---

## 1. 固定端口映射 (`127.0.0.1:21000+`)

- 为当前有效配置及 `Profile Mixin` 展开后的每个可用节点自动分配一个独立、持久化（`nodeServices.v1`）的本机端口（从 `21000` 起）。
- 仅绑定回环地址 `127.0.0.1`，同一端口同时提供 **HTTP 与 SOCKS5（含 UDP）** 混合入站协议，可直接填入浏览器扩展（如 SwitchyOmega / ZeroOmega）或命令行工具（`http://127.0.0.1:21000` / `socks5h://127.0.0.1:21000`）。
- 即使订阅节点顺序变动、密码更新或节点临时下线后重新出现，既有的端口映射仍会尽量保持不变，避免外部扩展配置失效。
- 支持界面勾选启用/停用、自定义端口号以及保留/冲突端口冲突校验；开启 [AI 专用锁定](AI-PROXY-LOCK.md) 时，每个固定端口仍会对 AI 流量强制执行 Fail-Closed 保护。

---

## 2. 单节点真实下载测速

点击 **测速** 后，客户端会按顺序通过每个已启用节点的固定端口请求 Cloudflare 官方测速端点：

- 默认测试 URL：`https://speed.cloudflare.com/__down?bytes=20000000`
- 单节点限制：**20 MB 上限** 或 **8 秒超时**，流式读取并丢弃数据，不写入磁盘，按实际接收吞吐量展示 `MB/s`；
- 串行逐个测速以防带宽互抢，支持随时取消，并在测速窗口期间自动暂停后台巡检避免干扰。

---

## 3. 自动健康巡检与 `DIRECT` 订阅刷新

- **巡检周期**：默认每 **60 秒** 并发检测已启用节点（最多 3 并发，单次超时 5 秒），依次使用 Google (`https://www.gstatic.com/generate_204`) 与 Cloudflare (`https://cp.cloudflare.com/generate_204`) 的 `204` 探测端点交叉核验。
- **连续失败触发刷新**：当节点连续失败达到阈值（默认 **3 次**）且满足冷却窗口（默认 **300 秒**）时，守护进程通过一个独立绑定 **`DIRECT` 出站** 的内部本机监听端口拉取最新托管订阅并触发事务式配置重载（避免因当前主节点彻底失联而导致订阅本身无法更新）。
- 网络离线、内核停止或配置切换期间自动跳过故障累计；下载或校验失败保留原运行配置与 `.runtime-last-good.yaml`。
